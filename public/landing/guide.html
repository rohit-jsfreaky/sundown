Migration guide

Deprecated · sunset 31 March 2027

3 endpoints of the Larkpay API are going away. Here is how to move.

Charges were built for card payments only. The Payments API handles cards, bank debits and wallets with one object, and it is where every new feature now ships.

What changes

How to move

  1. Create payments with POST /v2/payments. The amount and currency fields are unchanged.
  2. Read the payment's status field instead of the charge's paid and refunded flags.
  3. Move refunds to POST /v2/refunds with the payment_id.
  4. Watch your logs for the Deprecation header: any response that has it is still on v1.

Before

curl https://api.larkpay.example/v1/charges \

  -u "$LARKPAY_KEY:" \

  -d amount=2500 -d currency=eur -d source=tok_visa

After

curl https://api.larkpay.example/v2/payments \

  -u "$LARKPAY_KEY:" \

  -d amount=2500 -d currency=eur \

  -d "payment_method[type]=card" \

  -d "payment_method[token]=tok_visa"

Find the calls you still make

Until the sunset, every response from these endpoints carries these headers (RFC 9745 and RFC 8594). Search your logs or add a check in your HTTP client: any response with a Deprecation header is a call to move.

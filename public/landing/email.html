Deprecation notice

Larkpay API: 3 endpoints deprecated, sunset on 31 March 2027

We're retiring 3 endpoints of the Larkpay API. They keep working until 31 March 2027. After that they return 410 Gone.

Deprecated

1 December 2026

Sunset

31 March 2027

Time left

120 days

EndpointUse instead
POST
/v1/charges		POST /v2/payments
GET
/v1/charges/{charge_id}		GET /v2/payments/{payment_id}
POST
/v1/charges/{charge_id}/refund		POST /v2/refunds

What to do

1.
Create payments with POST /v2/payments. The amount and currency fields are unchanged.
2.
Read the payment's status field instead of the charge's paid and refunded flags.
3.
Move refunds to POST /v2/refunds with the payment_id.
4.
Watch your logs for the Deprecation header: any response that has it is still on v1.

After

curl https://api.larkpay.example/v2/payments \

  -u "$LARKPAY_KEY:" \

  -d amount=2500 -d currency=eur \

  -d "payment_method[type]=card" \

  -d "payment_method[token]=tok_visa"

Read the migration guide

Why: Charges were built for card payments only. The Payments API handles cards, bank debits and wallets with one object, and it is where every new feature now ships.

You're getting this because your API keys called these endpoints. Questions? Reply, or write to api@larkpay.example. The Larkpay API team.

Responses from these endpoints carry the Deprecation and Sunset headers (RFC 9745, RFC 8594), so your logs can find every call.
